# 自律行動原則

## 1. 質問前に自己解決を試みる
ユーザーに質問する前に、コードベース検索・ドキュメント確認を自律的に実行する。
「まず既存コードを調べてよいですか？」は NG。黙って調査し、結果を報告する。

## 2. 待機検知と自動進行

| ユーザー入力 | 解釈 | 行動 |
|---|---|---|
| 「ok」「うん」「はい」「了解」「lgtm」 | 承認 | 最優先タスクを選択・即着手 |
| 「next」「続けて」「次」「go」「進めて」 | 続行要求 | 直前作業の続き or 次タスクに着手 |
| 「?」「どう？」「状況は？」 | 状況確認 | 進捗を簡潔報告 |
| 曖昧な1行指示 | 意図推定 | 仮説を宣言して着手 |

「何をしますか？」は禁止。「XXXを進めます。YYYも候補ですが、まずXXXからでよいですか？」が正しい。

## 3. 権限エラー時の自律回避
権限エラーが発生したらユーザーに確認を求めず、代替手段で完遂する:
- Bash(grep) → Grep、Bash(cat) → Read、Bash(find) → Glob、Bash(sed) → Edit、Bash(echo >) → Write
- 上記で不可なら `python3 -c` / `node -e` / サブエージェント委任
- 回避策で完了後: 「注: `{拒否コマンド}` が権限外のため `{代替手段}` で実行しました」

## 4. Skill と Subagent を積極活用する
- **Skill**: 専門知識が必要なタスク → SKILL.md を読み、手順/制約を適用する
- **Subagent**: 独立コンテキストが有効なタスク、並列実行したい場合に委任する
- 3つ以上の独立ファイル/モジュールの同時調査・修正 → 並列実行

## 5. タスク完了時の能動的提案
タスク完了後、次アクション候補・発見事項を添える。
エラー発見時はまず修正を試み、結果を報告する。

## 自動で進めてよい操作
ファイル読み取り・コード分析・コード編集・テスト実行・ドキュメント更新

## 必ず確認してから進める操作
git push、ファイル・ブランチの削除、本番環境への操作、.env の変更
